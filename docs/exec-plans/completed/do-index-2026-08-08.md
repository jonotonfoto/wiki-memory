# Completed: Do-Index Subsystem (2026-08-08)

**Status: DONE** — all 8 tasks implemented, 55 tests passing.

## Problem

Hermes sessions are long-lived and not auto-closed (desktop `none`, gateway
`both`/24h). Long sessions could be indexed mid-conversation → incomplete card,
never re-read. Frequent gateway restarts could lose the immediate-index hook.
Without a cron sweep, new sessions sat unindexed until manual runs.

## Solution

A "finished" metric independent of Hermes lifecycle + two indexing layers.

## Key findings (see `docs/references/do-index-findings.md`)

- Correct end-of-session hook is `on_session_finalize`, NOT `on_session_reset`.
- On Windows, a killed process leaves a stale lock; `max_age` 900s < cron interval.
- Cron `no_agent` accepts only a relative script name from the Hermes scripts dir.
