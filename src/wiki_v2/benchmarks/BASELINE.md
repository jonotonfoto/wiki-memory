# Baseline Results for Associative Search (S2.5.0)

## Configuration
- Embedding model: nv-embedqa-e5-v5 (NVIDIA, 1024-dim) — база индексирована этой моделью
- Temperature: 0.0
- Date: 2026-08-12
- Code version: sandbox/wiki_v2 (правки 1.1-1.5, search.py:search)
- Search parameters: top_k=5, MIN_SEMANTIC_SCORE=0.40, MIN_KEYWORD_SCORE=0.30
- API state during run: normal (не degraded)
- Run script: benchmarks/_run_s250.py

## Results
- **Recall@5: 0.238** (5/21 запросов нашли ожидаемую страницу) — BASELINE (без QE)
- **MRR: 0.206** — BASELINE

## S2.5.2 — после Query Expansion (прогрет кэш, 2026-08-12)
- **Recall@5: 0.476** (10/21) — **+100% от baseline** 🎉
- **MRR: 0.273** — **+33%**
- Метод: кэш QE прогрет через expand_query (nemotron, 3 варианта/запрос, 665с), затем benchmark с тёплым кэшем
- QE реально находит страницы, которые без перефразов терялись

## S2.5.3 — после гибридного BM25+RRF (2026-08-12, без QE)
- **Recall@5: 0.524** (11/21) — **+120% от baseline** 🎉 (выше, чем QE 0.476!)
- **MRR: 0.353** — **+71% от baseline**
- Метод: BM25 по full_text (русский root-stemming) + векторные ранги, объединены RRF (_hybrid_merge). Хрупкие пороги (0.40/0.35/0.30) deprecated, не используются для merge (убраны из top_k_cosine и keyword-merge)
- BM25 компенсирует слабости векторного поиска — сам по себе (без QE) даёт 0.524
- После фиксов tester (реальный _hybrid_merge + убран min_score): 126 тестов зелёные, benchmark стабилен

## Notes
- Baseline зафиксирован на ТЕКУЩЕЙ реализации (двухуровневый: semantic + keyword).
- Слабые места: ассоциативные запросы БЕЗ точного совпадения слов почти всегда проваливаются — текущий поиск опирается на буквальные совпадения. Это ровно то, что должна улучшить фаза 2.5 (Query Expansion, гибрид BM25+RRF, мульти-вектор).
- Топ-результаты часто засоряются тестовыми страницами («привет», «ок», «план-анализа-отзывов») — возможно, из-за высоких embedding-скороев на общие темы.
- Сравнение после каждого этапа 2.5 — ТОЛЬКО при одинаковом конфиге (модель эмбеддинга, top_k, дата).
